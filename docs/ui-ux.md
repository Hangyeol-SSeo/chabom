# 화면 재구성 · 2026-09-22

## 설계 근거

- [Nielsen의 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/): 현재 상태 표시, 기억 대신 화면에서 식별하기, 최소한의 문구, 오류 복구.
- [단계적 정보 공개](https://www.nngroup.com/articles/progressive-disclosure/): 주요 작업을 먼저 배치하고 부가 정보는 요청할 때 표시.

기존 화면은 긴 소개, 입력 폼, 결과가 한 열에 이어졌고 차량/딜러 관리의 진입점이 분리되지 않았다.
사용자 테스트 연구를 새로 수행한 것은 아니며 위 원칙으로 구조를 정리하고 구현 후 브라우저 흐름을 검증했다.

## 정보 구조

1. 차량 보관함을 시작 화면으로 사용한다. 차량명, 가격, 연식/주행거리, 출처를 먼저 보여주고 원문 URL은 ‘원문 보기’ 링크로 줄인다. 전체/찜 필터와 검색, 가격/최근순 정렬을 제공한다.
2. 매물 확인은 링크 입력과 차량 확인으로 나눈다. 기본 정보와 핵심 5개 이력을 우선 보여주고 딜러 정보 수정과 추가 항목은 접는다. 판정은 미확인/결격 항목을 먼저 표시하고 통과 항목의 설명은 접는다.
3. 딜러 관리는 찜/블랙리스트/전체 탭으로 나눈다. 이름, 사이트, 연락처, 지역을 표시하고 긴 식별 ID는 접는다. 관련 저장 차량으로 이동할 수 있다.

## 상태와 접근성

- 블랙리스트 등록 시 사유를 입력하고 기존 딜러 찜을 해제한다. 찜 자체는 검증 결과를 변경하지 않는다. 제외를 해제한 뒤 다시 찜할 수 있다.
- 저장 데이터는 기존 SQLite를 유지한다. 기존 딜러 테이블에는 favorite 컬럼만 추가해 블랙리스트와 사유를 보존한다.
- 로딩/빈 목록/검색 결과 없음/네트워크 오류를 구분한다. 실패한 변경을 성공한 것처럼 표시하지 않는다.
- 라디오 필드셋, 입력 레이블, 버튼 상태, 키보드 포커스, 상태 알림, 기본 dialog의 포커스 관리를 사용한다.
- 데스크톱은 좌측 메뉴와 상세 화면의 보조 영역을 사용하고, 모바일은 상단 메뉴와 한 열로 전환한다.

## 검증

임시 DB와 로컬 서버에서 실제 Chromium으로 차량 찜/검색/정렬, 딜러 찜/수동 추가/제외/해제,
새로고침 후 보존, 제외 딜러 검증 보류, 원래 사고 내역 보존, 수동 입력 및 모바일 폭을 확인했다.
